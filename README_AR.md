# حساباتي – AZHA | تحديث 1.5.0 | الفواتير والتصميم الجديد

هذه الحزمة مشروع Android + موقع GitHub Pages وليست APK جاهزاً. تم تطويرها انطلاقاً من نسخة 1.4 دون تغيير مفتاح تخزين البيانات `hisabati_azha_v1` ودون تعديل سجل المقبوضات عند إصدار الفاتورة.

## الإضافات الجديدة

- تصميم محسّن بألوان الأسود والعنابي والأحمر والذهبي، مع تمييز المبالغ المقبوضة بالأخضر والباقي بالأحمر.
- شريط تنقل سفلي للهاتف، زر «فاتورة» في الأعلى، واختصارات سريعة في لوحة التحكم.
- قسم «الفواتير»: فواتير وعروض أسعار بأرقام وتواريخ، بيانات الزبائن، أي عدد من البنود حتى 100 بند، كميات وأسعار وخصم ورسوم إضافية، مع معاينة أثناء الإدخال.
- إنشاء الفاتورة وتعديلها وإضافة وحذف البنود وحذف الفاتورة بكاملها، مع البحث والتصفية.
- اختياري: ربط الفاتورة بشغل سابق لجلب بيانات الزبون وقيمة الشغل والمقبوض الفعلي، دون إنشاء دفعة جديدة أو تضخيم الدخل.
- تصدير الفاتورة PDF عبر نافذة الطباعة، بطباعة A4 مناسبة أو حفظ PDF. يُمكن مشاركة الملف بعد حفظه من تطبيق الملفات.
- زر «إرسال»: يشارك تفاصيل الفاتورة نصياً مباشرة عبر Android أو قائمة مشاركة المتصفح؛ وليس إرسال PDF تلقائياً.
- لم يتم تغيير شعار AZHA ADVERTISING ولا اعتماد «إعداد وتصميم: المهندس معز محفوظ علي أبو سيف» و«(الرجاء الدعاء لوالدي)».

## تنبيهات مالية مهمة

الفواتير مستندات ورقية/رقمية، وليست قيود دخل. إنشاء فاتورة أو عرض سعر أو تعديله لا يؤثر في إجمالي المقبوض أو الأرباح أو الديون. عند ربطها بشغل يظهر المقبوض من دفعات ذلك الشغل. لا يمكن إدخال دفعات لفاتورة مستقلة داخل قسم الفواتير؛ سجل الشغل والدفعات أولاً إذا أردت تتبع التحصيل في لوحة التحكم. إذا أنشأت أكثر من فاتورة للشغل ذاته فقد تظهر نفس دفعات الشغل في كل فاتورة: لا تجمع أرصدة الفواتير على أنها دفتر قبض مستقل.

إذا تباين إجمالي الفاتورة مع قيمة الشغل المرتبط، يظل سجل الشغل هو مرجع حساب الدفعات والأرصدة؛ الفاتورة ليست تعديلًا تلقائيًا لسعر الشغل.

هذه نسخة محلية من دون خادم مزامنة، لذلك لا تنتقل بيانات شخص إلى هاتف شخص آخر ولا تظهر سجلاتك السابقة في نسخة التطبيق النظيفة. ملف النسخة الاحتياطية JSON غير مشفّر، فلا تضع بياناتك الخاصة داخل مستودع GitHub العام.

## تحديث GitHub

1. من التطبيق الحالي افتح الإعدادات وحمّل نسخة احتياطية JSON قبل أي تحديث.
2. فك ضغط ZIP الرسمي، وارفع الملفات والمجلدات **داخل** ZIP إلى جذر المستودع `Hsaby/main` وليس ZIP نفسه.
3. يجب أن ترى في الجذر: `index.html`, `azha-logo.png`, `app`, `.github`, `build.gradle`, `settings.gradle`, `gradle.properties` وغيرها.
4. استبدل `app/src/main/assets/index.html` وكذلك `index.html` في الجذر بملفَي الإصدار الجديد. لا ترفع ملفات ZIP التجريبية.
5. GitHub Pages يستعمل `main/(root)`؛ GitHub Actions يقوم ببناء `app-debug.apk` تحت Artifacts بعد رفع الملفات.
6. هذه الحزمة لا تتضمن APK جاهزاً، ولم تُختبر مشاركة Android على هاتف حقيقي حتى الآن. البناء والتثبيت يتطلبان التحقق بعد تشغيل GitHub Actions.
7. قد تحتاج APK موقّعًا بمفتاح ثابت لتحديث التطبيق دون حذف بياناته. لا تحذف التطبيق القديم قبل نسخ بياناتك احتياطياً.

## طريقة استخدام الفواتير

- افتح «الفواتير»، اختر «فاتورة» أو «عرض سعر»، وأدخل اسم الزبون والتاريخ.
- اضغط «إضافة بند»، اكتب وصف الخدمة والكمية والسعر. يمكنك زيادة البنود أو حذفها.
- إن رغبت أن تظهر الدفعات المقبوضة من شغل معروف، اختر ذلك الشغل من قائمة الربط.
- اضغط «حفظ الفاتورة». بعد ذلك تستطيع تعديلها أو حذفها أو طباعتها أو إرسال تفاصيلها من السجل.
- للطباعة أو PDF: اضغط «PDF»، ثم اختر الطابعة أو «حفظ كملف PDF» من نافذة Android / Chrome. بعد الحفظ يمكنك مشاركة ملف PDF بالطريقة المعتادة.
- للإرسال السريع: اضغط «إرسال»، واختر WhatsApp أو الرسائل لمشاركة نص منسق بالتفاصيل.

## الاختبار

تم اختبار إنشاء فاتورة ببندين (600 + 150) وخصم 50 = 700 د.ل، تعديلها، حذفها، حفظها في الحالة، وربط فاتورة بشغل 1000 د.ل عليه عربون 300 د.ل، والتأكد من عدم إضافة قيمة الفاتورة إلى الدخل. كما تم توليد عينة PDF من صفحة A4 وفحص الصورة الناتجة. **اختبار APK على هاتف فعلي وإشعاراته والطباعة Android ما زال مطلوباً**.

# حساباتي – AZHA | الإصدار 1.4 – متابعة إنجاز الأشغال والتنبيهات

هذه الحزمة مخصصة للرفع إلى `https://github.com/moazabosef-alt/Hsaby`، وهي **مشروع مصدر GitHub Pages + Android**، وليست ملف APK جاهزًا. جميع الأوراق/الأشغال والأسماء التجريبية موجودة **فقط داخل ملف المعاينة المنفصل** ولا تتضمنها ملفات هذا المشروع.

## الجديد في الإصدار 1.4 – الحالات والتنبيهات

- لكل شغل حالة منفصلة عن حالة دفع المال: **لم يبدأ حتى الآن**، **قيد الانتظار/التنفيذ**، **جاهز للتسليم**، **تم التسليم**. تظهر أمام كل شغل في «أشغال الزبائن» و«أشغال الدعاية».
- بطاقات تفاعلية في قسم الدعاية تلخّص عدد الأشغال التي لم تبدأ، وقيد التنفيذ، وتم تسليمها، ويمكن الضغط للتصفية. تتوفر تصفية مستقلة في السجل لحالة إنجاز الشغل وحالة التحصيل.
- لكل شغل تاريخ تسليم وساعة اختيارية، ويمكن تعديلها لاحقًا من نفس البطاقة، ويظهر تنبيه أحمر للمواعيد المتأخرة وأصفر للقريبة.
- تذكير Android أصلي **كل 3 أو 4 ساعات** (أو 5 للسجلات القديمة التي اختارت ذلك)، ما دام هناك عمل غير مُسلّم، حتى لو أغلقت التطبيق. ويتضمن أعداد غير المبدوءة والقيد التنفيذ وأعداد المتأخرة، ويصدر صوت الإشعارات حسب إعدادات الهاتف.
- تنبيه إضافي عند حلول أقرب موعد تسليم مسجّل، مع إعادة جدولة المواعيد التالية. التوقيت **تقريبي**؛ Android قد يؤخر التنبيه بسبب توفير البطارية ولا يضمن دقة الدقيقة.
- عند تغيير حالة الشغل إلى «تم التسليم» يُستبعد تلقائيًا من تذكيرات الأعمال غير المنجزة، ويستمر ظهور ديون الزبون المتبقية إن وجدت. التسليم **لا يسجل أي دخل مالي**.
- يحتفظ استيراد/تصدير النسخة الاحتياطية JSON بحالة كل شغل وموعده، ويقرأ حالات الشغل القديمة دون تغيير سجلات الدفعات.
- **تنبيه مهم للويب:** تنبيه الصوت في المتصفح يعمل فقط والصفحة مفتوحة، وقد تمنع إعدادات المتصفح صوت التشغيل التلقائي. الإشعارات في الخلفية دون فتح الصفحة تتطلب تثبيت نسخة Android وإعطاء إذن الإشعارات.

### الاستخدام

1. في «أشغال الدعاية»، سجّل شغلًا وحدد حالة «لم يبدأ» أو «قيد الانتظار» واختر تاريخ وساعة التسليم.
2. افتح «متابعة إنجاز أشغال الدعاية»، واضغط بطاقة الحالة أو استخدم القائمة لعرض الأشغال المتأخرة/قيد الانتظار/المسلمة.
3. أمام الشغل غيّر الحالة مباشرة، أو عدّل موعد الإنجاز واضغط «حفظ الموعد».
4. من «الإعدادات» اختر تنبيه كل 3 أو 4 ساعات، ثم «حفظ الإعدادات». اسمح بإشعارات Android، وتأكد من أن صوت إشعارات قناة «تذكيرات حساباتي» غير مكتوم.
5. استخدم زر «تجربة التنبيه» لاختبار صوت وإذن إشعارات Android. لا تعتمد على إشعار التذكير وحده للمواعيد الحرجة.

### الترقية بدون فقدان البيانات

**قبل تثبيت أي APK جديد صدّر نسخة JSON احتياطية من داخل البرنامج.** قد يُوقَّع APK التجريبي من GitHub Actions بمفتاح مختلف عن الإصدار المثبّت، وعندها لا يمكن تحديثه فوق القديم. لا تحذف التطبيق القديم أو بياناته قبل التأكد من نسخة احتياطية قابلة للاستيراد. بيانات الهاتف المحلية لا تُنقل تلقائيًا إلى الموقع والعكس.

**نتيجة الاختبار:** اجتاز JavaScript اختبار الصياغة واختبار متصفح لإنشاء شغلين، وتغيير الحالات، وحفظ الساعة والتاريخ، والتصفية، والحفاظ على المبلغ المقبوض، وقراءة سجل قديم. لم يُبنَ APK في هذه البيئة ولم تُختبر إشعارات Android على هاتف فعلي؛ يجب تجربتها بعد بناء APK من GitHub Actions.

- تسجيل اسم الزبون والهاتف والطلب والقيمة الكاملة وتاريخ التسجيل والتسليم والعربون المقبوض.

- التذكيرات والتقارير اليومية والشهرية الموجودة سابقًا محفوظة، وتُدرج مبالغ الموردين المدفوعة في مصروف النشاط والنقد.
- شعار AZHA ADVERTISING ثابت، وتوقيع: «إعداد وتصميم: المهندس معز محفوظ علي أبو سيف» و«(الرجاء الدعاء لوالدي)».

## الفرق بين السعر والإيراد
- **القيمة الكاملة للشغل**: المبلغ المتفق عليه مع الزبون، حتى لو لم يدفع.
- **المقبوض فعليًا**: مجموع العربون والأقساط المستلمة المسجلة بالتواريخ.
- **باقي الزبون**: قيمة الشغل − المقبوض (يتحول إلى أخضر عندما يصبح صفرًا، ويظهر بالأحمر عند وجود باقي).
- **الربح المتوقع** = قيمة الأشغال الجديدة المسجلة خلال الفترة − التكلفة الكاملة للمواد المسجلة لها (قد تتغير لاحقًا).
- **صافي النقد في الفترة** = الدفعات المقبوضة في الفترة − المبالغ المدفوعة فعليًا للموردين في الفترة.
- **الربح المتوقع ليس الربح المحاسبي النهائي**؛ ولا يتضمن تلقائيًا كل مصروف تشغيلي غير مسجل أو الضرائب.
- مصاريف الموردين تظهر ضمن تقرير نشاطك ولا ينبغي إعادة إدخالها في المصروفات العامة لتجنب الازدواج.

## طريقة الرفع (مهم)
1. قبل تغيير APK الحالي، **صدّر نسخة احتياطية JSON من تطبيقك** واحفظها بأمان. لا تحذف النسخة القديمة قبل أخذ النسخة.
2. فك ZIP على الكمبيوتر، وافتح المجلد المستخرج.
3. ارفع **المحتويات** وليس ملف ZIP نفسه إلى جذر فرع `main` في GitHub، مع السماح باستبدال الملفات القديمة، بما فيها `.github/workflows/build-apk.yml` وملف `index.html` داخل `app/src/main/assets` وملف `index.html` في الجذر.
4. تأكد أن `azha-logo.png` موجود في الجذر وبداخل مجلد Android assets كما هو.
5. GitHub Pages: Settings → Pages → Deploy from a branch → `main` و `/(root)`.
6. لبناء APK: Actions → `Build Hisabati AZHA Android APK` → Run workflow (أو تلقائيًا بعد التحديث). بعد النجاح حمّل `Hisabati-AZHA-APK` من قسم Artifacts، وفك ZIP ثم ثبّت `app-debug.apk`.
7. **توقيع debug قد يتغير** بين عمليات البناء؛ إذا رفض Android الترقية، لا تحذف التطبيق القديم قبل تصدير نسخة JSON وإيجاد وسيلة لاستيرادها في النسخة الجديدة.

## خصوصية وتوافق
- النسخة لا تحتوي أي بيانات عملاء أو كلمات مرور مسبقة، ويبدأ كل مستخدم بحساب فارغ على جهازه.
- بيانات الموقع تحفظ محليًا في ذلك المتصفح، وبيانات APK تحفظ داخل التطبيق؛ **لا يوجد تزامن تلقائي بينهما**.
- احتفظ بنسخ JSON؛ تنظيف المتصفح أو حذف التطبيق قد يؤدي إلى ضياع البيانات. ملف النسخ JSON غير مشفر.
- GitHub Pages ينشر كود البرنامج علنًا، لكن الحسابات التي يدخلها المستخدم لا تُرفع تلقائيًا إلى المستودع.
- لا حاجة إلى استضافة مدفوعة أو خدمة بيانات خلفية لهذه النسخة.
- لم يتم إنشاء APK جديد في بيئة الإعداد هذه؛ بناء APK يتم عبر GitHub Actions بعد رفع المشروع، ويحتاج اختبارًا على هاتف حقيقي بما يشمل إشعارات الخلفية.

# حساباتي — AZHA | مشروع Android الخاص — الإصدار 1.2.0

هذه النسخة مبنية على `index.html` الأصلي الذي سلّمته من Gemini، وعلى تحديث القبض والديون السابق. **هذا الملف مشروع Android كامل، وليس APK مثبتًا جاهزًا**. حافظت على الواجهة السوداء والذهبية، وأضفت شعار AZHA ADVERTISING الذي زودتني به إلى شاشة الدخول والتطبيق وأيقونة أندرويد.

## الميزات الجديدة

- **لوحة البداية**: بطاقات قابلة للضغط لكل قسم، تظهر الديون المتبقية لك وعليك، وصافي الدخل والمصروفات، وعدد الأشغال غير المسلّمة، والمقبوض والمتبقي من الأشغال، والقيمة الكلية للأشغال وصافي الشهر الجاري.
- **التقرير اليومي**: اختيار أي تاريخ وعرض المقبوض من الأشغال والدخل اليدوي والمصروفات والديون الجديدة ودفعات سدادها والحركات المفصلة، مع الأرصدة الحالية بوضوح.
- **التقرير الشهري**: كل ما في التقرير اليومي، مع صافي نشاط الأعمال المصنف، وعدد الأشغال الجديدة والمسلّمة، وحركة الديون.
- **تصنيف العمليات اليدوية**: «النشاط التجاري / شخصي / غير مصنف»؛ يساعد على عدم وصف مصروفات المنزل بأنها خسارة للنشاط. القيود القديمة تظل «غير مصنفة» إلى أن تعدّلها.
- **نظام إشعارات Android**: إشعار ملخص اليوم في الساعة 23:00 افتراضيًا، أو 23:30، أو 00:00 عن اليوم السابق حسب إعداداتك. إشعار الشهر السابق في **اليوم الأول من كل شهر الساعة 00:10**. عند النقر على إشعار تُفتح الفترة المقصودة في التقارير بعد فك القفل.
- **PDF مجانًا**: افتح التقرير ثم اضغط «تقرير PDF». على Android تظهر شاشة الطباعة؛ اختر «Save as PDF / حفظ كملف PDF» ثم اختر مجلد الحفظ.
- **Excel مجانًا**: اضغط «تنزيل Excel (CSV)». ينتج ملف UTF-8 مع BOM يفتح في Microsoft Excel أو Google Sheets، وفيه ملخص وحركات الفترة. لا تحتاج إلى اشتراك.
- **بدون استضافة**: لا يوجد إذن INTERNET في `AndroidManifest.xml`، والسجلات تبقى محليًا على هاتفك. يدعم استيراد/تصدير نسخ JSON الاحتياطية من الإصدار السابق.

## قاعدة الحسابات المهمة

1. تسجيل شغل جديد أو تأكيد تسليمه **لا يزيد الدخل** تلقائيًا؛ يدخل إلى الدخل فقط العربون أو الدفعة المقبوضة بالفعل.
2. **صافي الدخل والمصروفات** = الدخل اليدوي المقبوض + دفعات الأشغال المقبوضة − المصروفات. لا يشمل تمويل السلف والقروض.
3. **تغير النقد شامل حركة الديون** = صافي الدخل والمصروفات − سلف أعطيتها للناس + سدادها إليك + ديون أخذتها − سدادها منك. وهذه حركة نقدية، لا تساوي بالضرورة رصيدك البنكي الفعلي لعدم تسجيل رصيد افتتاحي.
4. **صافي النشاط المصنف** = دفعات الأشغال المقبوضة + دخل يدوي مصنف «نشاط تجاري» − مصروفات يدوية مصنفة «نشاط تجاري». هذا مؤشر مبسط لتقدير الربح أو الخسارة، **وليس أرباحًا محاسبية معتمدة**؛ خاصة إذا نقصت تكاليف الإنتاج أو اشتملت السجلات على مصروفات غير مصنفة.
5. الأرصدة المتبقية المعروضة ضمن تقرير قديم هي **الأرصدة الحالية الآن** وليست بالضرورة كما كانت في نهاية ذلك اليوم أو الشهر.
6. عدد الأشغال الجديدة/المسلمة يبدأ بتسجيل تواريخ الأحداث في الإصدار 1.2؛ قد لا يمكن استنتاج التواريخ الماضية لأشغال سابقة على الترقية.
7. إشعار التقرير يظهر ملخصًا فقط؛ التفاصيل الكاملة تظهر داخل قسم التقارير وتُصدر PDF أو CSV.

## ضبط الإشعارات

1. ثبّت APK وافتح التطبيق، ثم أنشئ اسم مستخدم وكلمة مرور خاصة (على الأقل 8 أحرف).
2. افتح **الإعدادات** ← «موعد إشعار ملخص اليوم»، واختر 11:00 ليلًا أو 11:30 أو 12:00 منتصف الليل.
3. فعّل التقرير اليومي والشهري واضغط «حفظ الإعدادات».
4. **اسمح بالإشعارات** عندما يسألك Android (مطلوب على Android 13 أو أحدث).
5. يُستخدم `AlarmManager.setAndAllowWhileIdle`؛ قد يتأخر الإشعار عن الموعد المطلوب وفق توفير البطارية/قيود النظام. بعد إعادة تشغيل الهاتف يعيد البرنامج جدولة التذكيرات. لم تُختبر الإشعارات على هاتف حقيقي بعد.

**ملاحظة:** التذكير اليومي عند 23:00 يتناول كل المعاملات المسجلة حتى وقت الإشعار؛ إذا أردت تضمين اليوم كاملًا، اختر 00:00 عن اليوم السابق. ويأتي التقرير الشهري الساعة 00:10 من اليوم الأول في الشهر التالي ليغطي الشهر المنتهي. البيانات تُحسب بحسب التاريخ المدخل في الحركة، ويمكنك العودة للتقارير القديمة في أي وقت.

## بناء APK من هاتفك بدون جهاز كمبيوتر

1. افتح https://github.com/new وسجّل الدخول.
2. أنشئ مستودعًا باسم `hisabati-azha-private` واختر **Private** (خاص، وليس عامًا).
3. فك ضغط ZIP الذي أُرسل إليك؛ ارفع **محتويات المشروع** إلى GitHub، بما فيها مجلد `.github/workflows` (قد يكون مخفيًا في بعض مديري الملفات).
4. افتح المستودع في GitHub → **Actions** → **Build Hisabati AZHA Android APK** → **Run workflow**.
5. عند نجاح البناء افتح الـ Artifacts ونزّل `Hisabati-AZHA-APK`؛ بعد فك ضغطه تجد `app-debug.apk`.
6. افتح `app-debug.apk` على هاتف Android وثبّته. لا تحتاج إلى Google Play.

بديل ذلك فتح المشروع في **Android Studio** على كمبيوتر يدعم JDK 17 وAndroid SDK 35 وGradle 8.9 ثم Build APK(s).

**تنبيه حول الترقية:** APK من GitHub Actions (debug) قد يُوقع بمفتاح مختلف في كل بناء، وقد لا يُثبت فوق الإصدار السابق. احتفظ دائمًا بنسخة احتياطية JSON قبل تغيير التطبيق أو حذفه. لإصدارات يمكن تثبيتها فوق بعضها بدون مسح البيانات، استخدم توقيع Release بمفتاح ثابت تحتفظ به أنت في مكان آمن. يجب عدم مشاركة مفتاح التوقيع أو كلمات المرور هنا.

## حماية بياناتك

- لا يتم نشر بيانات الديون والزبائن تلقائيًا؛ المشروع ليس خدمة ويب ويعمل دون اتصال.
- قفل البرنامج يحفظ تجزئة كلمة المرور وليس نصها الصريح، ولكن **بيانات السجلات نفسها على الهاتف ليست مشفرة تشفيرًا كاملًا**؛ فعّل قفل شاشة الهاتف.
- **ملف JSON الاحتياطي غير مشفر**. احفظه خارج متناول الآخرين. في الترقية من Gemini لا تُستورد كلمة المرور المكشوفة السابقة.
- إشعارات التقارير تعرض مبالغ مالية؛ أُعدّت على Android لتكون خاصة على شاشة القفل، لكن عرض تفاصيلها يعتمد أيضًا على إعدادات إشعارات الهاتف.
- مسح بيانات التطبيق أو حذفه قد يُفقد سجلاتك إذا لم تحفظ نسخة احتياطية.
- ملفات HTML للمعاينة ليست بديلًا عن APK؛ إشعارات Android بالخلفية وطباعة PDF عبر النظام تحتاج تشغيل نسخة Android الفعلية.
